Compared with each package's latest previously approved registry release. These notes describe the published 0.12.2 artifacts; adding notes does not replace their blobs.

  • Refreshed package SDK headers and import libraries from the release build; rebuild project C++ code against this engine and these package versions.
  • This release has Windows components only. Linux and macOS games stay on the 0.12.0 packages until those platforms are rebuilt.

plasma.ai 1.5.2

Previous: 1.5.1

  • An agent pushed off its path corridor, by physics or a teleport, searches a new path from where it is instead of asserting.
  • An object that is no agent, such as a player or a turret, states its team through the stimulus source it makes its noises with.
  • Unity builds compile: runtime file-local helpers and the legacy behaviour score no longer share names, and the editor plugin builds its views without unity batches.

plasma.csharp 1.4.2

Previous: 1.4.1

  • Engine calls are typed: generated bindings pass arguments in stack memory with no argument arrays, boxing or pinned buffers (0 bytes per call, was 432), resolve through a per-snapshot call plan without the binding lock, and return small values inline.
  • Exposed fields can be typed engine components: the editor shows an object picker and the script receives that object's component.
  • Typed blackboard keys (BlackboardKey<T>), a Variant struct for 'any value' slots without boxing, and engine lists as Variant[], so SpawnPrefab, multi-result queries and params-style functions are generated.
  • [KeepOnReload] carries marked members across a full reload by name.
  • Timers and game-time waits (After, Every, Delay, NextFrame, Until, Run); async continuations, including Task.Delay, resume in the script's Update and are dropped when it goes away.
  • Maths helpers: dot, cross, lerp, slerp, quaternion and transform operations, time and angle arithmetic, System.Numerics conversions.
  • Save-game, settings and platform clients created in a script callback belong to that script and are disposed with it.
  • The generator reports lifecycle methods that never run, misplaced inspector attributes and [PlasmaScript] on structs (PLCS010-PLCS012).
  • Update dispatch takes no lock and makes no allocation in the common case; the handle registry looks objects up through an identity index (20000 objects: 25 us to 62 ns).
  • Stability fixes for unload and retire, self-deleting scripts, stale handles, variant vectors, console command world access, source filtering and package path repair.

plasma.networking 1.4.2

Previous: 1.4.1

  • Every peer sends and receives through a simulating driver with seeded per-peer conditions; net_sim presets persist and reorder works without jitter.
  • Servers send only to admitted clients through one send API, outgoing messages queue first in first out, and the replication tick runs on a fixed accumulator.
  • Spawned components are named by object and slot, spawns carry initial state, clients hold state and RPCs until components start, and one owner lookup decides authority, including the host's.
  • RPCs follow one routing table for every target and caller, arguments are converted before a call and a mistyped call is dropped.
  • Stopping ends the session's objects and time sync, a leaving client's objects go with it, and disconnect and shutdown reasons reach the other side.
  • NetworkTest covers spawn, ownership, RPC routing, blackboards, level travel, client-owned state, lifecycle and every simulator preset.

plasma.vegetation 0.4.2

Previous: 0.4.1

  • Vegetation cells draw foliage composite types natively: instanced part meshes near the camera, the merged mesh beyond, with parts, part shadows and bones limited by distance.
  • Composite trees share per-tile wind variants and promote to their own bone instances near the camera, under touch or when pinned, keeping their bend as they switch.
  • Far foliage: a merged voxel shell for middle distances and impostors toward the horizon, both off by default (Vegetation.CellShell.Enabled, Vegetation.Impostor.Enabled).
  • Vegetation is persistent ray tracing content, and Vegetation Types get a Ray Tracing group (Affects GI, Ray Tracing Mesh, Ray Tracing Range).
  • Fill mode scatters the checked plants over a rectangle or the whole layer with Poisson-disk spacing, Clearing mode paints areas Paint and Fill keep out of, and Fill also runs headless.
  • Vegetation Types carry Density Weight and Clearing Avoidance (type file v3; v2 loads with the old behaviour).
  • Layers re-register only the chunks a change touched, so strokes and fills on large layers stay interactive.
  • Vegetation cell batches are not pickable, so clicks and the brush reach the surface under the trees and hover picking stays cheap.
